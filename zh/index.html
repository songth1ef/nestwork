01 / 问题

每个新会话，
都从零开始。

你花一下午教会一个 agent 你的技术栈、你的规矩、项目进行到哪一步。换个会话、换台电脑、换个工具——全没了。你又得把自己的「病历」从头背一遍。

ERR_01

记忆锁在一台机器上

公司电脑上的 agent 懂你的规矩，笔记本、云服务器、手机上的那个一片空白。

ERR_02

被一家厂商锁死

Claude 的记忆只喂 Claude，Codex 的只喂 Codex。一换工具，辛苦攒的上下文全留在原地。

ERR_03

agent 之间互不通气

一个 agent 刚记下的坑，隔壁机器上的另一个 agent 第二天照样踩进去。

ERR_04

记忆不归你所有

订阅到期、地区限制、账号丢失，任何一件都能让你攒了几个月的上下文一夜清零。

“我明明在 A 机器上让 agent 记下了『这个部署脚本有个坑』，B 机器上的 agent 第二天又踏踏实实踩了一遍。”

—— 摘自《我用 git 给 16 个 AI agent 装了同一个大脑》

02 / 工作原理

一个仓库，
一个大脑。

nestwork 不是一个要你部署的服务，而是一套 agent 共同遵守的协议。记忆就是 你自己私有 git 仓库 里的普通 markdown。每个 agent 读之前先 pull、写之后立即提交，于是一个 agent 学到的东西，下一个会话里所有 agent 都能用上。

01

创建你的私有记忆仓库

在 GitHub 点 Use this template，设为 private。仓库在你自己的账号下，不经过任何第三方。

02

每个工具跑一行安装脚本

在每台机器上 clone，然后给 Claude Code、Codex、Gemini、Kimi、Hermes 或 OpenClaw 跑对应安装脚本，自动接好启动加载和同步 hook。

03

照常干活就行

每次写记忆前 hook 自动 pull --rebase，写完立即 commit + push。任何机器上打开任何 agent，它都已经认识你。

your-nest/ # private git repo — the shared brain ├── queen/ # rules & strategy · human-owned, read-only for agents ├── shared/ # cross-agent memory · topic files + generated index ├── agents/ │ └── <host>/<agent-id>/ # each agent writes ONLY here → no write conflicts ├── projects/ # live project state └── workflow/ # portable methods that follow you between jobs
queen/agent-rules>queen/strategy>shared>agents/*>projects>workflow

权威链：两处说法冲突时，高层说了算——agent 不会把矛盾的指令搅在一起。

03 / 能长期积累的上下文

像 skill 一样
按需加载。

上下文不是越多越好：模型真正能用好的注意力，远小于标称的上下文窗口。所以 nestwork 从不把你的全部历史一股脑塞进提示词。

  • 常驻层，约 640 token。 启动时只读核心规则和两份简短摘要，字节预算由脚本检查。
  • 主题索引。 记忆拆成一个个主题文件，每个都带一行 description，写明什么时候该读；memory.md 是自动生成的路由表。
  • 只打开命中的。 要做 git 操作？agent 只打开 git-discipline.md。记忆可以积累好几年，单次会话依然轻快。

04 / 你会得到什么

一切，
都是文本文件。

git-only

永远不需要服务器

没有数据库、没有常驻进程、没有托管 API。存储、历史、冲突 git 早就解决了，nestwork 直接复用。记忆就是普通文件，随处可读。

cross-tool

六种工具，一个大脑

为 Claude Code、Codex CLI、Gemini CLI、Kimi Code、Hermes、OpenClaw 提供安装脚本，任何用 markdown 配置的 agent 也能用通用脚本接入。

conflict-free

为多 agent 而设计

每个 agent 独占 agents/<host>/<id>/。逐次写入的原子 hook 自动 pull → 写 → commit → push 并重试，几十个 agent 同时写也不互相覆盖。

3.1

主题记忆

skill 式路由：自动生成的索引 + 主题文件。--check 会拦住索引过期、缺描述或文件过大。

distill

记忆蒸馏

用 claude -p 或 codex exec 把各 agent 的私有笔记合并进共享记忆——只做并集、从不删除、由人审核。

mailbox

agent 之间能留言

一个 agent 往自己的发件箱写一条，另一台机器上的 agent 协作时就能读到。没有消息队列、没有中间件，就是一个文件加一次 push。

git-crypt

可选加密

开启 git-crypt 后，git 托管方看到的只有密文，agent 读写的依然是明文 markdown。

carryover

把工具记忆救出来

Claude Code、Codex、Kimi 的原生记忆都只存在单台机器上。把它们蒸馏进你的仓库，换电脑、换工具、丢账号都不怕。

08 / FAQ

常见问题。

nestwork 是什么？

nestwork 是一套面向 AI 编程 agent 的 git 原生记忆协议。一个私有 git 仓库用普通 markdown 保存你的规矩、偏好、踩坑经验和项目上下文，你用的每个 agent——Claude Code、Codex CLI、Gemini CLI、Kimi Code、Hermes、OpenClaw——都读写同一个仓库。结果就是一份跨会话、跨机器、跨厂商的长期记忆，而且带版本历史。

怎么让 Claude Code 和 Codex 共享记忆？

在每台机器上 clone 一次你的记忆仓库，然后分别运行 scripts/install/claude.sh 和 scripts/install/codex.sh。两个工具会拿到指向同一仓库的同一套启动协议：在 Claude Code 里记下的规则或教训，Codex 下个会话就能用，反之亦然。每个工具只写自己的目录，互不覆盖。

Claude Code 的记忆能跨机器同步吗？

它自己不能。截至 2026 年，Claude Code、Codex、Kimi Code 的内置记忆都只存在本机。nestwork 把其中值得长期保留的上下文放进 git，新电脑或云服务器 git clone 一下就有了。你也可以把工具的原生记忆蒸馏进仓库，这样换机器、换工具、丢账号都不会丢。

记忆越攒越多，会不会把上下文窗口撑爆？

不会，协议正是为此设计的。启动时 agent 只读很小的常驻层：核心规则加两份简短摘要，在作者的仓库上约 640 token，而全量加载要约 69,600 token。其余都按需读取：memory.md 是自动生成的主题索引，每个主题文件都有一行「什么时候该读」的描述，agent 只打开与当前任务匹配的文件。

nestwork 是向量数据库或 RAG 吗？

不是。没有 embedding，也没有检索服务。记忆就是人能直接读的 markdown，可以像 git 里其他文件一样打开、编辑、diff 和审阅。检索方式和 agent 使用 skill 一样：读一份简短的索引，挑出相关文件，再读它。

需要部署服务器或付费吗？

不需要。没有托管服务、没有常驻进程、没有数据库，只有 git 和你仓库里的几份 shell / Python 脚本。托管在 GitHub、GitLab、自建 Gitea 或任何你已有的 git 远端都行。断网时 agent 仍能读取记忆；在装了同步 hook 的工具上，写入记忆需要能连上远端。

很多 agent 同时写，会冲突吗？

每个 agent 实例独占自己的目录 agents/<host>/<agent-id>/，日常写记忆根本不会碰到同一个文件。在支持 hook 的工具上，每次写入前自动 pull --rebase，写完立即 commit + push，失败会重试。共享记忆只在明确触发、经人审核的蒸馏中才会被改写。

敏感的记忆能保密吗？

把仓库设为私有，对大多数人已经足够。如果连 git 托管方也不能看到，可以开启可选的 git-crypt 模式：agent 读写明文，提交进 git 的全是密文。无论是否加密，都不要把 API key 或密码写进记忆，它们应该放在专门的密钥管理工具里。

它和 AGENTS.md / CLAUDE.md 有什么区别？

单个仓库里的 AGENTS.md 只描述那一个代码库。nestwork 用同样的文件格式，作为一个「用户级记忆仓库」的启动协议：你的身份、偏好、跨项目的经验和在飞项目状态，会跟着你进入每一个仓库、每一个工具；各项目自己的 AGENTS.md 照常生效。

团队可以用吗？

可以，但建议从小处开始：一个私有仓库，每个 agent 实例一个目录，规则放在由人维护、agent 只读的 queen/ 里。分层的权威链决定谁的指令优先，共享规则保持稳定，每个 agent 又各自保留自己的笔记。
